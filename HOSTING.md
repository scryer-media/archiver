# Static hosting security contract

Build with `npm run build` and serve the complete `dist/` directory over HTTPS (localhost is suitable for local testing). No deployment is performed by the build. Apply `public/_headers` as **HTTP response headers** on HTML, JavaScript, WASM, workers and other static assets. Merely serving that file or copying these directives into an HTML meta tag is insufficient: worker policies, framing protection and isolation require response headers.

Vite production preview reads this exact file through `scripts/production-headers.mjs`. Development keeps its existing isolation headers without the production CSP, so Vite module transformation and HMR remain available. Preview is a local verification server, not a deployment configuration for an arbitrary host.

## Policy

The production Content-Security-Policy denies resources by default, limits scripts, dedicated/service workers, connections, styles, images, manifests and download frames to the same origin, and refuses plugins, base-URL changes, form submissions and embedding. Only `wasm-unsafe-eval` is permitted for local WebAssembly compilation. JavaScript string evaluation, inline scripts/styles and blob workers are not allowed. Output Blob downloads remain explicit user actions; they are not worker script sources. The same-origin iframe route is needed for streamed downloads.

This is defense in depth, not a guarantee that arbitrary same-origin code is safe. Same-origin requests remain allowed for native runtime/module loading, offline installation and downloads. Keep the origin dedicated to static app assets; do not add upload endpoints, relays or remote asset imports. CSP does not replace archive validation, dependency review or browser security fixes.

## Cloudflare and other hosts

Production runs as an assets-only Cloudflare Worker (`wrangler.jsonc`) at `archiver.scryer.media`, built and deployed by Cloudflare Workers Builds on push. Build command `npm ci && npm run build`; deploy command `npx wrangler deploy`. [Workers static assets](https://developers.cloudflare.com/workers/static-assets/headers/) apply `dist/_headers` to every asset response and do not serve the file itself. Those rules never reach responses generated by Worker code, so keep the Worker script-free; adding one means setting the same headers in code. Another host must configure equivalent response headers explicitly. Check the actual public response, including worker scripts, instead of treating the presence of a file as proof.

Preserve COOP `same-origin`, COEP `require-corp`, CORP `same-origin`, the CSP, `Referrer-Policy: no-referrer` and `X-Content-Type-Options: nosniff`. Serve JavaScript and WASM with their correct MIME types. The [WASM-specific CSP allowance](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/script-src) permits compilation without granting JavaScript `unsafe-eval`.

The offline worker caches the verified HTML response with its headers. A downloaded update waits for existing pages to close; old open pages keep their prior policy until the new cohort is activated. Apply the policy on every deployment and verify a clean installation plus offline reload. Do not remove existing site data or force an update during an active job.

## Local verification

```sh
npm run check
npm run build
npm run preview -- --host 127.0.0.1 --port 4199 --strictPort
# In a separate terminal, after preview is ready:
node tests/production-csp.mjs http://127.0.0.1:4199/
```

The Node test checks exact header values on production HTML, a module and both service workers. The explicit browser runner `tests/run-production-csp.mjs --execute --url http://127.0.0.1:4199/ --endpoint http://127.0.0.1:9230` requires an idle owned test browser and a fresh preview origin. It uses actual production ZIP/sniffer/native/helper workers, small exact-hash outputs, one 64 KiB completed streamed download, an offline reload with the HTTP cache disabled, and deliberately blocked inline/external-connect probes. It closes only its own tab and removes only its own OPFS jobs. These are bounded compatibility checks, not a large-archive benchmark or a public-host audit.
